如果你手上有一份调了很久、能正常工作的配置，这页是你最该先看的。

结论：**BootAgent 在覆盖任何配置文件之前，都会先留一份带时间戳的备份**，而且它不会覆盖你现有配置里与它无关的部分。

## 备份文件长什么样

备份和原文件在同一个目录，文件名是原名加后缀：

```
~/.openclaw/openclaw.json
~/.openclaw/openclaw.json.backup-20260806143022
```

时间戳是 UTC 的 `年月日时分秒`。如果同一秒内发生了多次写入，后面会再加序号（`.backup-20260806143022-1`），所以备份之间不会互相覆盖。

原文件本来不存在时不会产生备份——没有东西需要保护，留一个空文件反而误导。

## 怎么退回去

把备份的文件名改回原名即可：

```
cd ~/.openclaw
mv openclaw.json.backup-20260806143022 openclaw.json
```

然后按[切换模型](/help/03-models/)里说的重启方式让 Agent 重新读配置。对 OpenClaw 是 `openclaw gateway restart`，不是重开终端。

## 它不会覆盖你的其他设置

这一点比备份更重要，因为它意味着多数情况下你根本不需要回退。

BootAgent 写配置时不是整份重写，而是读进你现有的文件、只改它负责的那部分。以 OpenClaw 为例，它在 `models.providers` 下加一个叫 `oneagent` 的条目，你原来调好的其他设置一个字都不动。

所以如果你担心的是"我那些自定义设置会不会没了"——不会。

## 写入是原子的

BootAgent 先写一个临时文件，确认落盘之后才替换正式文件。中途断电、进程被杀、或者写到一半报错，都不会留下一个写坏一半的配置文件——你要么拿到完整的新配置，要么原文件没被动过。

## 什么时候会被写入

只有你在确认页点了"开始安装"之后。在那之前，包括选 Agent、选 Provider、验证连接、选模型，全都不写任何文件。

确认页会明确列出这次要写入哪个文件，所以点之前可以核对。
