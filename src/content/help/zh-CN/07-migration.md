换机器、或者给同事一份现成配置时，可以把模型服务和配置模版导出成一个文件，在另一台机器上导入。

入口在设置页的"导入导出"。

## 导出

选择要带走的模型服务和配置模版，然后 BootAgent 会问你**是否加密**。

这一步的选择很重要，下一节单独说。

选完之后指定保存位置，得到一个文件。

## 关于加密：这一步别跳过

如果你导出的模型服务里存了 API Key，**选择不加密会把 Key 以明文写进文件**。

那个文件之后可能被放进网盘、发在群里、或者留在下载目录很久——任何拿到它的人都能直接读出你的 Key。

所以：

- **导出内容含 Key** → 选加密，设一个密码
- **只是想带走配置结构**（Provider 地址、模型选择），不含 Key → 不加密也可以

加密用的是 PBKDF2 派生密钥加 AES-GCM，密码不存在文件里。**密码无法找回**，丢了密码这个文件就作废了，没有后门也没有恢复途径。所以密码要用你能可靠取回的方式记住。

## 导入

在另一台机器的同一个入口选"导入"，选择文件。如果文件是加密的，会要求输入密码。

导入前 BootAgent 会先列出这个文件里有什么、将会新增或覆盖什么，你确认之后才真正写入。

## 几个报错的含义

**"密码错误，或文件已损坏"** — 这两种情况在密码学上无法区分：解密失败时拿不到任何线索说明是密码不对还是数据被改过。先确认密码，再确认文件是否完整传输。

**"这个文件的版本（N）不受支持，当前只支持版本 1"** — 文件来自比当前 BootAgent 更新的版本。升级这台机器上的 BootAgent 再试。

**"文件格式无效，请确认这是 BootAgent 导出的文件"** — 选错文件了，或者文件不是导出功能产生的。

**"模型服务数据格式无效，文件可能被手工修改过"** — 文件结构对但内容不符合预期，通常是有人用文本编辑器改过它。重新导出一份。

## 迁移不包含什么

导出的是模型服务和配置模版，**不包含已经写入各个 Agent 的配置文件**。

也就是说导入之后，新机器上还需要走一遍[配置流程](/help/03-models/)把模版套用到 Agent 上。这是刻意的：目标机器上装了哪些 Agent、装在什么位置，和源机器不一定相同，直接搬配置文件反而容易写坏。
