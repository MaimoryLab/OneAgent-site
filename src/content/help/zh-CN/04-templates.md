配置模版就是一份"Provider + 模型"的组合，起个你自己看得懂的名字存下来。之后给另一个 Agent 配置时直接选它，不用重新挑 Provider、重新填 Key、重新选模型。

如果你只用一个 Agent、一个 Provider，这个功能可以忽略。它解决的是"同一套模型服务要配给三四个 Agent"的重复劳动。

## 存一个

在配置流程的第二步，选"新建配置模版"，走完 Provider 和模型两步，确认页会把这次的组合存成模版。名字可以自己填。

## 套用

下次配置别的 Agent 时，第二步选"套用已有配置模版"。Provider 和模型两步会跳过——因为组合已经定了，没有新的凭证要引入，也没有新的连接要验证。

步骤指示器上那两步会显示为已跳过，不是被禁用。

## API Key 不在模版里

模版记录的是**用了哪个 Provider、哪个模型**，不含 Key。Key 单独存放，模版里只标记"这个 Provider 有没有存过 Key"。

这带来一个实际影响：把模版分享给同事，对方拿到的是配置结构而不是你的凭证。如果你确实要连 Key 一起迁移，那是另一件事，见[配置迁移](/help/07-migration/)，那里有需要注意的安全问题。

## 一个模版可以给多个 Agent 用

模版和 Agent 是分开的。同一个模版可以套用到 Codex、Claude Code、Opencode，各自写进自己的配置文件，互不影响。

反过来，改动一个 Agent 的配置也不会动到其他用同一模版的 Agent——模版是套用时的模板，不是持续同步的链接。这一点如果理解错，容易误以为改一处会全体生效。

## 在哪管理

侧栏的"配置模版"页列出所有模版，可以查看和删除。删除模版不会撤销已经写入 Agent 的配置——那些文件已经写好了，要改还是走[切换模型](/help/03-models/)的流程。
